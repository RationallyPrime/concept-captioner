## Lanes

**core.** The broken ChatGPT streaming is fixed. The transport used to read lines, which drops
the blank lines that separate server-sent events, so every event in a stream ran together. It
now passes raw bytes to a new WHATWG event-stream parser. That parser is tested with every line
ending split at every byte, and with a realistic Responses stream that goes through the real
`URLSessionTransport` and is cut inside the JSON. `openai` now uses the Responses API, as Python
does, and both Responses clients share one body encoder that always sends `store: false`, with
no way for `extra_body` to override it. Several settings that used to be inferred are now set
explicitly: Gemini's API type is its own setting instead of following from bearer auth, and
`resolve` chooses the OpenRouter reasoning dialect instead of looking at the host name. Redirects
to a different origin now drop every credential header. The vLLM key is tied to scheme, host and
port. `gateway/chat` and `gateway/responses` are now accepted. CORE-SPEC gained a dated revisions
table. A third commit, not in the task list, makes Swift resolve a job's relative `skill` and
`.md` profile paths against the job file's folder. Review blocked it because the spec claimed
Python already did this. `bd252e4` corrected the spec: the difference is now recorded as
Deviation 10, with the Python change proposed rather than made. Two things were skipped. Live
caption text while a caption is being written needs a progress hook across `ModelClient`,
`StructuredStage`, `Runner` and the UI, which is a signature change across lanes, so it is a
proposal for now. And the ChatGPT route has not been checked against a live stream, because the
tests make no network calls.

**python.** When no key is set, the vLLM path no longer depends on openai SDK internals. The
provider gets a placeholder key and an httpx client from pydantic-ai's public factory, plus a
request hook that removes `Authorization` before every send, including redirects. `resolve()`
accepts an `http_client` so tests can supply a transport. The openai and anthropic origins stay
pinned, and the docstring says why. The Pydantic AI Gateway upstreams are a finite list
(`GATEWAY_UPSTREAMS`), so an unknown upstream is now a configuration error instead of an
`ImportError`. `openai>=3.26,<4` is declared directly. Markdown is excluded from `ruff format`.
Nothing was reported as skipped. The lane said CI did not run the format check, but the docs
lane added it, and it passes on main.

**pod.** TensorBoard no longer uses the master bearer token as its browser cookie. A new
`POST /tensorboard-session` returns a session derived with HMAC that lasts 12 hours and works only
under `/tensorboard`, and the proxy now targets TensorBoard's fixed port. `GET /runs/{id}/files`
and `/runs/{id}/files/{path}` list a run's outputs and stream them. Both require the bearer and
refuse dot segments, absolute paths and symlinks. podctl gained `tensorboard`, `files` and `pull`.
`pull` verifies the size and SHA-256 and never writes outside the destination. The LTX-2 download
is pinned to a fixed revision (`dfcc2108`), runs before any run file is written, and exits 69 on
failure. TensorBoard is pinned to 2.21.0 in the LTX image, and the base image build fails if a
vLLM flag in the allowlist is missing from the installed package. POD-SPEC records the owner's
decision that the pod has no self-stop, because the app's cost guards cover it. The work is
source-only: the images have not been rebuilt, and none of it has run against a real pod.

**app-contract.** A custom skill is now copied into `<project>/skill/<name>/`, and `job.yaml`
refers to it as `./skill/<name>`. The bundled skill writes no `skill` key. Older projects that
point outside the folder are migrated when they are opened. The Hub dataset and training output
destinations now live per project in the app-only `.conceptstudio/project.json` and are never
published. Recent projects are kept in order of use, capped at 10, pruned when they no longer
resolve, and stored through the injected preferences. The GPU workspace receives the injected
preferences and a `SecretStore`. Provider defaults come from one `ProviderChoices` table, and a
model the user typed is kept when the provider changes. Money goes through one `StudioMoney`
formatter. The demo always lives in one temporary folder. Photos imports use `PhotosPicker`,
get stable readable names, and are converted to JPEG when the format is HEIC or another
unsupported one, which also drops the Photos entitlement. Hub import marks rows that had no
record as imported and can protect them as final. Caption runs and caption edits use separate
gates, and an action that is refused says why. Session methods no longer present panels; they
publish a pending confirmation for the window to show. Vision analysis runs in the background
with a cache keyed by content hash. The lane report was cut off after item 10, so anything it
skipped is not on record here.

**gpu.** Trained LoRAs are no longer stranded on the pod. With a Hub token, the finished run is
pushed to the project's output repo as a private model repo, or to the signed-in account when no
repo was chosen. Without a token, the final safetensors, the trainer config and samples are
downloaded through the agent into `<project>/results/<run-id>/`, and every SHA-256 is checked.
The result state is saved with the pod record and in `.conceptstudio/training.json`. While a
result is still pending, the idle stop is blocked and Stop everything refuses with a message;
only the budget may discard it. The app keeps the Mac awake while a pod runs. On launch it
adopts a running `ConceptStudio-*` pod whose local record was lost and lists any others as stray
pods. Review follow-ups fixed how the final checkpoint is picked when a run id ends in digits,
stopped a CPU pod in the listing from breaking reconciliation, and made the agent token
read-only outside the workspace. Nothing was reported as skipped. None of it has run against a
real pod.

**ui.** Close, quit and discard confirmations are now SwiftUI alerts driven by a prompt waiting
on the session. No `NSAlert.runModal` remains. Quitting with a computer running offers to keep
it running, shows the price and spend, and keeps Stop as the default. GPU pods, Training and

**docs.** APP-STATUS, CORE-STATUS and POD-STATUS were rewritten to describe the current state.

## Open decisions for the owner

Historical state at `36617c8`. The owner settled all five later on 2026-10-11 in the
[overnight review's fix-round decisions](overnight-review-2026-10-11.md#fix-round-decisions-decided-2026-10-11-afternoon).
Keep the original proposals below as the decision history; current contracts and verification
are in CORE-SPEC, POD-SPEC and their status documents.

1. **How Python resolves relative paths in a job file (CORE-SPEC Deviation 10).** Swift now
   resolves `skill: ./skill/<name>` and `.md` profile paths against the folder that holds
   `job.yaml`, but Python still resolves them against the working directory. So the CLI only
   runs an app project correctly when it is started from inside the project folder. Making
   Python match is small (`Job.load` keeps the folder, and the skill and runner loaders use it),
   and it makes the shared contract true from any directory. The downside is that it changes CLI
   behavior for anyone who relies on paths relative to the working directory. Recommendation:
   accept it, because the app's project folder is the contract and is meant to work from
   anywhere.
2. **Showing caption text while a caption is being written.** Streaming now works, but
   `ModelClient` returns only the finished reply, so the app shows nothing until a caption is
   complete. Showing progress needs a per-sample progress callback through `ModelClient`,
   `StructuredStage` and `Runner`, plus a place in the Captioning screen to show it. It gives
   users visible activity, which was the original request. The cost is a signature change in
   ConceptCore that the Python reference has no counterpart for, though it stays out of the job
   file and the response record. Recommendation: build it as an app-only hook that is not part
   of the shared contract.
3. **Training without a Hugging Face account (v0.2-plan, "Proposal for the owner").** The pod
   still gets its images by pulling a Hub dataset, so a user with no Hub account cannot train,
   which is the same gap already closed for the trained LoRA. The proposal is to upload the
   images, captions and `job.yaml` to the pod's network volume through the agent's authenticated
   API when no Hub token is set. This removes the last hard Hub dependency. It needs a new agent
   upload endpoint and an app upload step, and it moves private photos straight to the rented
   machine instead of through Hub. Recommendation: accept it; it matches the push-or-save rule
   already decided for the LoRA.
4. **Core contract edits the owner has not reviewed.** CORE-SPEC's revisions table lists changes
   made by implementing sessions that the owner has not approved one by one: openai on
   Responses, `store: false` everywhere, origin-bound credentials, and the Gemini API and
   reasoning-dialect settings. Each matches the Python reference or makes a credential check
   stricter. Recommendation: review the table once and approve or strike rows.
5. **The badge's money format.** The `Demo · $0` badge is a fixed literal, while other amounts
   follow the Mac's locale (`0,00 US$` on this machine). Either the badge goes through
   `StudioMoney`, which is consistent but longer, or all amounts are fixed to `$` with US
   formatting, which is consistent but ignores the locale. This is a small design call.
