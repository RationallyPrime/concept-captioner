## Scope

Use H3's base-mode syntax from MiniMax's `h3-prompt-writing` skill, with the Core Caption Policy above. These are proposed training captions, not a claim about a private pretraining dataset or measured optimal identity-caption recipe.

The fields below belong to serialized text. They are not automatically JSON keys, API arguments, or additional conditioning tensors. Use a JSON container only when the actual loader requires one.

## Three fields

Keep these names and order, with blank lines between fields:

```text
integrated_multimodal_description: [Shot 1] ...

overall_soundscape: ...

non_diegetic_music: ...
```

In the first field, introduce the target trigger and class noun in the opening description. Describe observed composition, controllable subject details, surroundings and lighting. For clips, develop actual action and scene-originating audio chronologically. Name visual style only when it is outside the learned concept.

Use the soundscape field for ambient sound, effects and nonverbal vocal sounds, without repeating speech or singing. Use the music field for an audible audience-only score. Prefer concrete audible properties to interpretations of the music's intended emotion.

## Stills

Use `h3-still` for one photograph or frame:

- One `[Shot 1]`, with no timestamp, cuts, duration, reference prefix, or temporal claims.
- Describe framing and visible pose. Do not assert a stationary camera or that a person starts, continues, or finishes an action.
- Set both audio fields to `N/A`.
- Retain the trigger, class noun, and meaningful visible nuisance details.

AI Toolkit's MiniMax image-captioning implementation supports this three-field still convention. The trainer must separately support image targets for the selected checkpoint. Do not create a fake video or claim that caption syntax establishes a training topology.

## Text-to-video/audio

For `h3-t2va`, begin directly with the three fields. Add no image-alignment line.

Start `[Shot 1]` without a timestamp. Number only real subsequent cuts, for example:

```text
[Shot 2] At 00:02.750, the camera cuts to a wider view ...
```

Use strictly increasing, segment-relative cut times within the actual target. Do not invent cuts to organize prose. Describe a continuous shot through sentences inside `[Shot 1]`.

For ordinary cuts, follow the timestamp with the native phrasing `the camera cuts to` or `the shot cuts to`, `transitions to`, `changes to`, or `switches to`. Describe a dissolve, fade, or wipe only when observed.

Distinguish camera translation, rotation and zoom only when supported by the footage. Use natural actions and meaningful range/speed. If the mechanism is unclear, describe the visible framing change without guessing.

Follow the actual temporal order. Do not extend a short clip, invent a final pose, rescript a performance, or impose the generation guide's suggested duration range on training data.

## Actual keyframe conditioning

Select these profiles from the real trainer configuration and conditioning sample. A still identity reference is not necessarily a first frame. Confirm image order after processing.

Preserve the native alignment line literally, replacing only endpoint placeholders with verified values. Follow it with a blank line, then the three fields. The alignment instruction is the formatting exception to otherwise observational prose.

### I2VA

When the trainer supplies the actual first frame as conditioning image one and expects H3's alignment text, prepend:

```text
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.
```

Establish the initial state using the trigger and explicit nuisance details, then describe only observed subsequent motion. Do not replace clothing, hairstyle, light, setting and pose with "as in the reference."

### FL2VA

When actual first and last images are supplied in that order, use:

```text
How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot N) aligns with the S.SS-second mark of the target video.
```

Replace `N` with the real final shot number and `S.SS` with the trainer's effective endpoint to two decimals. Describe the observed intermediate path. Do not infer it solely from endpoints when the target clip is unavailable.

### L2VA

When the supplied conditioning image is the real final frame, use:

```text
How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the S.SS-second mark of the target video.
```

Describe the observed opening and transition. The generation guide may invent an opening; training captioning may not.

Use the actual processor's endpoint convention. Do not silently interchange nominal duration, last-frame presentation time and effective model endpoint. If this is unknown, complete the descriptive body and hold the prefix-dependent sample for review.

### Ref2VA

Ref2VA is outside this standalone prompt's ready-made profiles. Do not force it into the three-field base format or invent reference packing. If it is explicitly requested, ask for the relevant six-section formatting and actual trainer-conditioning contract before producing a training-ready result. Continue other supported samples. This is a scope boundary, not a requirement to browse during ordinary captioning.

## Speech and sound

### Dialogue and speakers

- Use stable `(S1)`, `(S2)` IDs for actual speakers and singers, not silent people. Preserve IDs across cuts.
- Bind a speaker to a trigger only with evidence. Otherwise describe an off-screen voice without assigning the target's identity.
- Keep language and exact intelligible words inside native dialogue tags:

```text
NORA7, the woman beside the table (S1), says in a soft voice: <d>[English] Shall we begin?</d>
```

- Keep delivery, actions and voice attributes outside the tags. Describe nuisance voice attributes; omit defining timbre when voice identity is explicitly part of the target concept.
- Preserve original language and words. Do not reconstruct unclear dialogue from a known script, filename or plausibility. Verified transcripts may supplement inspection when aligned to the actual target audio.
- Use `(S1,S2)` only for actual simultaneous delivery. Different overlapping lines require distinct speaker attribution.
- Complex dialogue crossing cuts or ending mid-utterance requires the trainer's exact `<scenetrans>` / `<cutoff>` serialization convention. This standalone file does not prescribe unverified token placement. If such a case occurs and the rule is not supplied, preserve the verified transcript in a separately labeled draft, flag the formatting question, and hold that sample rather than guessing. Ordinary fully contained dialogue uses the complete format above.
- Use `says in an off-screen voiceover` when accurate. State that visible lips remain closed only when observed; never copy an inference instruction into contradictory training labels.
- Quote legible on-screen text with ordinary double quotation marks. Preserve its original spelling and language.

### Audio evidence

| Target condition | Caption treatment |
| --- | --- |
| Still image | Both audio fields `N/A`; optional separate status `not_applicable` |
| Inspected audiovisual target | Describe actual scene sound, speech and score in the appropriate fields |
| Verified completely silent target | Both audio fields `N/A`; separate status `verified_silent` |
| No audible audience-only score | `non_diegetic_music: N/A` |
| No audio in the training objective | Follow the trainer's documented no-audio representation; do not invent sound or assert the source was silent |
| Target audio uninspected | Hold for inspection; do not use `N/A` to encode uncertainty |

If only speech or score is present, describe the verified lack of additional ambient/action sound instead of inventing room tone. If the source of music is unclear, flag the classification separately; do not invent a radio or unseen orchestra.

For photos, `N/A` indicates absent audio content in this caption convention. It does not disable audio loss, create a mask, or configure H3 to learn silence.
